# Правила командной работы

## Язык проекта

Документацию, комментарии к коду, пояснения, названия задач и **сообщения коммитов** пишем **по-русски**, где это не нарушает совместимость.

Не переводим имена файлов и каталогов, Python-функций, классов и переменных, названия библиотек, аргументы команд, имена CSV-столбцов и стандартные сокращения (например, MAE, RMSE, ARIMA, MLP). Так другим участникам проще запускать и соединять модули.

Примеры сообщений коммитов:
- `Добавить проверку пропусков в данных XAU/USD`
- `Реализовать прогнозирование с помощью ARIMA`
- `Исправить расчёт метрики sMAPE`
- `Обновить описание временной валидации`

## Порядок работы

1. Перед началом проверить [EXPERIMENT.md](EXPERIMENT.md), особенно границы данных и правила временной валидации.
2. Получить актуальный код: `git pull origin main`.
3. Создать отдельную ветку под задачу, например `feature/data-cleaning` или `feature/arima`.
4. Писать код в согласованном модуле и добавлять проверки.
5. Выполнить `python -m pytest -q`.
6. Отправить ветку в GitHub и создать запрос на включение изменений (Pull Request).
7. Попросить другого участника проверить код и только после проверки объединить изменения с `main`.

Команды для создания ветки:

```powershell
git checkout main
git pull origin main
git checkout -b feature/data-cleaning
# После внесения изменений:
git add .
git commit -m "Добавить очистку котировок XAU/USD"
git push -u origin feature/data-cleaning
```

## Как должны работать модели

Каждая модель получает согласованный набор доступной на момент прогноза информации и возвращает таблицу с колонками `origin_date,target_date,horizon,model,y_pred`.

Не создавать индивидуальные несогласованные тестовые периоды. Не использовать фактическую будущую цену как признак и не подбирать параметры по тесту.

Сохранять параметры модели, правила предобработки, сведения о времени обучения и прогнозирования, случайные зерна и версию окружения.

## Что сдаёт участник

- Код своего компонента.
- Краткое описание метода и принятых решений на русском языке.
- Тесты или воспроизводимую процедуру проверки.
- Прогнозы и измеренные результаты (когда данные готовы).
- Текст и иллюстрации для README и выступления.

## Перед защитой

Вся команда проверяет запуск по инструкции из README, подготовленные CSV, таблицы, графики, корректность горизонтов и отсутствие утечек. Каждый участник должен быть готов ответить на вопросы по проекту целиком.

Не подменять отсутствие результата вымышленными метриками: отмечать незавершённые части открыто.
