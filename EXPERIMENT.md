# План эксперимента

Пока это рабочий план. Окончательно зафиксируем даты обучающей и тестовой выборок после подготовки дневных торговых сессий. Исходные котировки уже выгружены; подробности в [DATA.md](DATA.md).

## Задача и гипотезы

Прогнозируем цену закрытия XAU/USD на **1 и 5 торговых дней вперёд** по истории за 12 месяцев на 28 октября 2026 года.

Проверим три гипотезы:

- **Г1.** На горизонте 1 день хотя бы одна модель точнее Naive по MAE.
- **Г2.** На горизонте 5 дней хотя бы одна модель точнее Naive по MAE.
- **Г3.** При прогнозе на 5 дней средняя абсолютная ошибка больше, чем при прогнозе на 1 день, если считать её по одним и тем же исходным датам.

Результат заранее неизвестен: гипотезы могут не подтвердиться.

## Какие методы сравниваем

| Метод | Как строится прогноз |
|---|---|
| Naive | Берём последнюю известную цену закрытия для обоих горизонтов |
| ARIMA | Строим статистический прогноз временного ряда |
| Random Forest | Обучаем отдельную модель для каждого горизонта на исторических признаках |
| MLP | Обучаем небольшую нейросеть для каждого горизонта |

Признаки и параметры ARIMA, Random Forest и MLP подбираются только на обучающих данных с временной валидацией. Учитываем, что в распоряжении всего год наблюдений.

## Как будем проверять модели

Обозначим цену закрытия после сессии `t` как `C[t]`. После её завершения строим прогнозы `C[t+1]` и `C[t+5]`. Под «днём» понимаем торговую сессию, которую ещё предстоит определить по данным Dukascopy.

- Для итоговой проверки предварительно оставляем последние **около 20%** ряда. Остальные наблюдения используем для обучения и подбора параметров.
- На обучающей части проверяем модели на нескольких следующих друг за другом временных отрезках с расширением истории.
- При обучении на конкретную дату используем только признаки и целевые цены, которые к этой дате уже известны. Для прогноза на пять дней это особенно важно.
- Масштабирование и другие преобразования настраиваем только по обучающей части соответствующего окна.
- На тесте все модели строят прогнозы для одних дат `t`, причём для каждого `t` должны быть доступны фактические `C[t+1]` и `C[t+5]`.
- Заранее решаем, будут ли модели обновляться по мере поступления данных на тестовом участке. Подбирать параметры по итоговому тесту нельзя.

В `src/validation.py` уже есть функции для разбиения по индексам и ограничения доступности целевых значений. Подключим их к эксперименту только после утверждения торгового календаря.

## Что считаем

Основная метрика — **MAE** (средняя абсолютная ошибка), в долларах США за тройскую унцию. Также считаем:

- **RMSE** — корень из средней квадратичной ошибки.
- **sMAPE** — `100 × среднее(2|прогноз − факт| / (|факт| + |прогноз|))`. Если обе цены равны нулю, вклад наблюдения принят равным нулю.
- **Точность направления** — процент совпадений знаков `прогноз − C[t]` и `факт − C[t]`. Для Naive прогнозируемое изменение равно нулю, поэтому эту метрику разберём отдельно.

Сравниваем MAE и остальные метрики на одинаковых датах. Дополнительно рассматриваем ошибки на разных участках теста, отличия между горизонтами и время обучения/получения прогнозов.

## Какие файлы должны получиться

Каждая модель возвращает:

```text
origin_date,target_date,horizon,model,y_pred
```

Общий модуль добавляет фактическую цену `y_true` и цену на исходную дату `origin_close`. В итоговом README покажем таблицы, графики, параметры моделей, версии библиотек, ограничения и выводы.

Пока реальные прогнозы не рассчитаны. Следующий шаг — согласовать границы торговых дней и подготовить `data/processed/`.
